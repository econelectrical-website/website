# econelectrical.co.uk

The Econ Electrical website. Static pages generated by a small Python build, served
by Netlify, with no framework and no database.

## How a change reaches the live site

Netlify watches this repository. Push to `main` and the contents of `site/` go live at
econelectrical.co.uk within a minute or so. There is no build step on Netlify: the
finished pages are committed here, so there is nothing that can fail during a deploy.

That is deliberate. Building here, where the fonts, the image library and ffmpeg all
exist, and committing the result, is far more reliable than asking a build server to
reproduce the same environment.

If a deploy ever goes wrong, every previous one is kept in the Netlify dashboard and
can be republished with two clicks. Rolling back is quicker than fixing forward.

## Layout

    site/                 the finished website; this is what Netlify publishes
    build/                everything needed to regenerate site/
      build.py            the generator: pages, navigation, sitemap, redirects, schema
      site_content.py     the words. Services, projects, team, older blog posts
      blog_posts.py       the newer blog posts
      landing_pages.py    service landing pages, and which articles each one links to
      encode_video.py     video encoding. Run it when a clip changes, not every build
      add_team.py         team portraits, cropped from the originals
      add_photos.py       project photography
      media.py            the original image pipeline, from the WordPress library
      check_links.py      every internal link resolves
      check_text.py       typography and content checks
      static/             site.css and site.js, copied into the build as they are
      _assets/            the image and video library the build draws from
      originals/          source files that cannot be regenerated. Keep these

## Rebuilding

    cd build && python3 build.py

Writes `build/dist/site` (the real site) and `build/dist/preview` (the same pages with
file relative links, for previewing without a server). Copy `dist/site` over `site/`
and commit.

Needs Python 3 and Pillow. ffmpeg is only needed by `encode_video.py`, not by a
normal build, though `build.py` will use `ffprobe` if it is there to read video
dimensions, and falls back to a sensible guess if it is not.

Always run the checks before pushing:

    cd build && python3 check_links.py && python3 check_text.py

## Things worth knowing before changing something

**Video filenames carry a content hash** (`econ-team-on-site.c0c11cd6.mp4`), generated
at build time. This is not decoration. Videos are cached for a year, and before the
hashes existed a re-encode published under the same name kept being served from cache
for a week after it was replaced. Do not remove the hashing without also dropping the
cache lifetime back down.

**Each video has a phone sized cut** alongside the full one, and `site.js` chooses
between them. It has to be script rather than two `<source>` elements with a `media`
attribute, because Chromium ignores `media` on a video source and hands a 390px phone
the desktop file. This was tested, not assumed.

**Some project photography is portrait**, shot on a phone, and a page hero is a wide
shallow band, so those crop hard. A project can set `hero_focus` to move the crop up or
down the frame.

**Client confidentiality.** Two of the bus depot projects are published without naming
the client, and some photographs are cropped in `add_photos.py` to keep a sign or a
branded vehicle out of frame. Those crops are recorded in the script on purpose, so a
rebuild cannot quietly undo them.

**Published figures are calculated, never invented.** Where a project page claims a
saving, the working is in a comment next to it in `site_content.py`.

**`originals/` holds what cannot be remade.** The hero video source had to be recovered
from the live site once, after the original export was lost. The camera originals for
the two project videos are much larger and are not in this repository; Jonathan has
them.

## Short addresses

`build.py` writes `_redirects`, which includes short addresses used in print. `/solar`
is on a roadside banner's QR code, so that one is load bearing. Check `_redirects`
before removing anything that looks unused.
